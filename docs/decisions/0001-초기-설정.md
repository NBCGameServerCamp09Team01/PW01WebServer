# 0001. 웹서버 초기 설정

- 상태: 채택
- 날짜: 2026-10-05 결정, 2026-10-06 반영
- 결정: Sang-Hyun-Kim(파트 d, PM). 원래 G0에서 c(Robbie)와 정하려던 항목(W08~W10, W28~W32, W39)도 먼저 정했고, G0(10/6)에서 Robbie와 팀에 안내했다. 바꿀 점은 후속 PR로 고친다.

## 배경

- 과제 두 개(basic: crimson-citadel, expert: webcraft)를 각 프로젝트의 AI 에이전트가 분석한 보고서를 근거로 39개 항목(W01~W39)을 정했다.
- 두 과제 모두 비밀값을 커밋했고 CI가 없었다. basic은 테스트가 0개였다. 이번에는 반대로 간다.
- 연동 기간(10/6~10/13)이 1주라, 첫 실제 API(S1)를 바로 시작할 수 있는 틀이 필요했다.

구현하면서 더한 것:

- 시각은 밀리초까지 자른다(Auditing 시각 공급자 + `DATETIME(3)`). 응답 JSON과 DB 값이 같아지고 UE가 읽기 쉽다.
- Instant는 `hibernate.type.preferred_instant_jdbc_type=TIMESTAMP`로 MySQL `DATETIME`에 매핑한다.
- 표에 없는 HTTP 오류(404·405·415 등)는 상태 이름을 오류 코드로 쓴다.
- 통합 테스트는 `@IntegrationTest` 하나로 묶어 컨테이너를 한 번만 띄운다.
- `.editorconfig`로 모든 파일을 UTF-8로 연다(`.properties`의 한글 주석 보호).
- 프로필을 정하지 않고 실행하면 `local`로 뜬다(`spring.profiles.default=local`). 첫 로컬 실행에서 프로필을 빠뜨려 DB 설정을 못 찾은 일이 있었다. 테스트는 `test` 프로필을 직접 붙인다.
- Redis 저장소(`@RedisHash`) 스캔을 끈다. Redis는 RedisTemplate으로만 쓴다.

## 근거

- 버전 조합(Boot 4.1 + Gradle 9.5.1 + JDK 21): 두 과제에서 JPA·Redis·WebSocket·Testcontainers까지 동작했다.
- Flyway + validate: 팀원 네 명이 같은 스키마를 쓰고 변경 이력이 남는다.
- Testcontainers: 중복 반영 방지·락은 실제 MySQL에서 시험해야 한다. expert는 테스트가 통과한 뒤 실서버에서 매퍼 차이로 실패했다.
- 오류 본문: expert의 기계용 코드와 basic의 사람용 메시지를 합쳤다.
- 모르는 필드 400: UE와 서버의 필드 이름이 어긋난 것을 조용히 넘기지 않는다. 응답에서는 게임이 모르는 필드를 무시하므로, "응답 필드 추가는 호환되는 변경"이라는 확장 약속과 함께 지킬 수 있다(루트 `docs/contracts/README.md`).

## 결과

- 웹서버 첫 PR은 커밋 12개다: 골격 → 설정 → compose → 테스트 → CI → 공통 오류 틀 → 예시 API → 문서(C1~C8), 빠진 파일 보충(C9), 문서 보정(C10), CI의 `gradlew` 실행 권한(C11), 그리고 이 기록을 맞춘 문서 커밋.
- 루트 PR #1(기준 브랜치, DS 정리, 공통 API 규칙, 예시 명세)이 먼저 병합됐다.

## 대가

- 테스트에 Docker Desktop이 필요하다(Testcontainers).
- 요청에 필드를 더할 때는 서버를 먼저 배포해야 한다(모르는 필드 400).
- 예시 API가 규칙처럼 굳을 수 있다. 그래서 `example` 패키지에 가두고, 클래스마다 "학습용"이라고 표시하고, S1 병합 때 지운다.
- c의 영역(오류 형식, DTO·변환 규칙)을 G0 전에 정했다. 바꿀 점은 후속 PR로 고친다.

## 고르지 않은 대안

| 번호 | 대안 | 고르지 않은 이유 |
|---|---|---|
| W09 | 클래스 + Lombok `@Getter` | record는 불변이고 생성자 인자 순서 실수가 줄어든다 |
| W10 | Service 안에서 생성자 호출(두 과제 방식) | 같은 변환 코드가 여러 곳에 복사되고 인자 순서가 바뀌어도 컴파일러가 못 잡는다 |
| W10 | 별도 Mapper 클래스 | 파일이 늘어난다. 변환이 복잡해지면 그때 옮긴다 |
| W11 | `application.yml` | 들여쓰기를 틀리면 기동이 실패한다. 두 과제가 properties였다 |
| W12 | local·dev·prod(+test) | 팀이 함께 쓰는 개발 서버가 아직 없다 |
| W13 | Spring이 `.env`를 직접 읽기 | 로컬 편의일 뿐 AWS에서는 쓰지 않는다 |
